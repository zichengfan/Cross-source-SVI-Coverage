## 1. Summary

Já 360 is the street-level panorama service of **Já.is**, Iceland's national
phone-directory / mapping portal (operated by Sýn hf.). It launched in 2013 and
covers Reykjavík and the capital region plus many rural towns, villages and
roads across Iceland — in places broader than Google Street View (Westman
Islands, the West Fjords, etc.). It is an **active, first-party** SVI provider
for an entire country, in scope as a **Tier-1** provider. It is not defunct, not
a re-hoster, and not paid-B2B: the panoramas and their coverage map are served
free through the public `ja.is/kort` map viewer. This subplan scrapes the
viewer's **Já 360 coverage overlay** — the vector tile layer that draws "a 360°
photo exists on this road" when the 360 mode is toggled in the viewer — and
rasterizes it onto the shared z14 coverage grid. Only coverage presence is
stored; no panorama imagery is downloaded.

## 2. Research findings (filled by provider-scout)

### Verdict: Já 360 serves a VECTOR (MVT) coverage tile layer

The ja.is/kort viewer is a **Mapbox GL JS v1.13.1** map. Its map style
(`ja-streets.json`) declares a dedicated **`ja360` vector tile source** plus two
style layers that draw it; toggling the viewer's "360°" button makes those
layers visible. There is **no rendered raster `{z}/{x}/{y}` PNG overlay** for
360 coverage (unlike kakao/naver/mapy) — the coverage is a vector source.
Therefore `ja360` is a `kind="vector_mvt"` provider, the same shape as
`panoramax`, `mapillary` and `apple_lookaround`. All evidence below was gathered
from the live viewer assets (see "How the overlay was identified").

- **Homepage / public viewer URL:** `https://ja.is/` ; the map + 360 viewer is
  at `https://ja.is/kort/` (English: `https://en.ja.is/kort/`). A panorama opens
  via permalink `https://ja.is/kort/?nz=17&x=<isn93_x>&y=<isn93_y>&ja360=1&jh=<heading>`
  — note those permalink coordinates are ISN93 and are **not** used by this
  provider (see "Coordinate scheme").

- **Tier:** T1 — first-party national SVI provider with a public coverage tile
  layer. This is the last unbuilt T1 provider.

- **Source kind:** `vector_mvt` (existing kind — `source_kinds/vector_mvt.py`).
  No new source kind is needed. The provider mirrors
  `src/coverage_acquisition/providers/panoramax.py`.

- **How the overlay was identified.** The `ja.is/kort` HTML loads its map app
  bundle from CloudFront:
  `https://d1u1k9z2dfyx06.cloudfront.net/dist/map-<hash>.js`. That bundle builds
  a Mapbox GL map whose `style` is
  `<MAP_TILES_URL>ja-streets.json`, where `MAP_TILES_URL` is read from an inline
  `<script id="map_tiles_config">` →
  `https://tiles.aws-prod.ja.is/static/styles/ja-streets.json`. The style JSON
  (`"name": "Já Kort"`, Mapbox style spec `version: 8`) declares:
  - a vector source **`ja360`**:
    ```json
    "ja360": {
      "type": "vector",
      "tiles": ["https://tiles.aws-prod.ja.is/tilesets/v15/ja360/tiles/{z}/{x}/{y}.pbf"],
      "bounds": [-24.5326, 63.2957, -13.4947, 66.5665],
      "minzoom": 4,
      "maxzoom": 14
    }
    ```
  - two style layers drawing it, **`Já 360 driveline casing`** and
    **`Já 360 driveline`** — both `"type": "line"`, `"source": "ja360"`,
    `"source-layer": "driveline"`, initial `"layout": {"visibility": "none"}`.
  The app bundle's 360-control class toggles them on when the viewer's "360°"
  button (`.action-360` / `map-control-360`) is clicked:
  ```js
  addLayer() {
    this.map.setLayoutProperty("Já 360 driveline","visibility","visible");
    this.map.setLayoutProperty("Já 360 driveline casing","visibility","visible");
  }
  ```
  So the **`driveline`** layer of the `ja360` MVT tileset is exactly the "Já 360
  imagery exists on this road" coverage overlay. (The viewer's separate panorama
  *imagery* tiles — `…/ja360-tiles/mres_<face>/…jpg` and the
  `api-ja360.aws-prod.ja.is` blur API — are the photos themselves and are **not**
  used by this provider.)

- **Coverage endpoint:**
  - **URL template:**
    `https://tiles.aws-prod.ja.is/tilesets/v15/ja360/tiles/{z}/{x}/{y}.pbf`
  - **HTTP method:** `GET`. No query string.
  - **Tileset version:** the path segment `v15` is a tileset-version directory
    (the sibling `openmaptiles` basemap is `v16`, the hillshade `v1`). It is a
    static path component, **not** a per-request token — pin `v15` in the
    template and treat a future bump (style JSON `ja360.tiles[0]` changes) as a
    re-scrape trigger, not a live-discovery step. **No `runtime_config/`
    handler is needed** for `ja360`.
  - **Required headers:** the endpoint could not be probed from the project's
    scraping host (see robots/ToS), but the viewer issues a plain `GET` with no
    auth. Set `SourceDefinition.headers` for a polite scrape: a descriptive
    `User-Agent`, `Referer: https://ja.is/kort/`, and
    `Accept: application/vnd.mapbox-vector-tile, application/octet-stream;q=0.9, */*;q=0.1`
    (same posture as `panoramax`).
  - **Query params:** none.

- **Coordinate scheme:** **`web_mercator`** — standard EPSG:3857 / WGS84
  spherical-Mercator XYZ slippy tiles, 256-unit MVT extent, OpenMapTiles-style
  `{z}/{x}/{y}.pbf`. The `ja360` source sits in the **same Mapbox GL style** as
  the `openmaptiles` OSM basemap source, which is plain web-mercator; Mapbox GL
  vector sources are always web-mercator XYZ. **No custom grid, no new
  `coordinate_scheme`, no foundation prerequisite.** (Já.is uses the ISN93 /
  `EPSG:3057` Lambert projection only for viewer permalink coordinates — that is
  irrelevant here; the tile grid is web mercator.) `geo.py`'s existing
  `web_mercator` branch covers tile-range and tile-bounds for this provider as-is.

- **Zoom range / tile size / response format:**
  - The `ja360` source advertises **`minzoom: 4`, `maxzoom: 14`** (overzooming
    above 14 is done client-side by Mapbox GL — z14 is the deepest *fetchable*
    tile). z14 is exactly the project's analysis grid zoom.
  - Response format: a **Mapbox Vector Tile** (`.pbf`, protobuf, typically
    gzip-encoded on the wire — `vector_mvt`'s `maybe_gzip_decompress` handles
    that). The tile contains a **`driveline`** layer of `LineString` /
    `MultiLineString` features tracing the streets that have Já 360 coverage.
  - There is no fixed raster "tile size" — MVT tiles carry geometry, not pixels.
  - Capture-date layer: the `driveline` features' attribute schema could not be
    inspected from our blocked host. The 360 *imagery* API exposes a per-pano
    capture month (`find_panorama_by_id` → `month`, `YYYY-MM`), but whether the
    `driveline` MVT features carry a year/date attribute is **unverified**. Treat
    a `ja360_year.tif` date layer as **out of scope** for this provider PR; the
    implementer should inspect the decoded feature properties during the pilot
    and note in §6 whether a date attribute exists for a possible follow-up.

- **Auth:** **none** — no token, no cookie, no API key, no signed URL. The tile
  endpoint is a public, unauthenticated CDN/S3-style path referenced directly by
  the public map style. **No `.env` key is required or added** for `ja360`. (The
  viewer's homepage carries a Cloudflare Turnstile widget for some interactive
  features, but the static map style and its tile sources are not behind it.)

- **Presence rule:** "Já 360 imagery exists here" = the decoded MVT tile's
  **`driveline` layer contains ≥ 1 feature**. The `vector_mvt` source kind
  decodes each `.pbf` into feature records (`feature_count`); a tile with
  `feature_count > 0` in the `driveline` layer is **covered**, a tile that
  decodes to **zero** `driveline` features is **checked-empty**. The decoded
  `LineString` geometries are written to `data/intermediate/ja360/` as the
  re-rasterizable source of truth and burned onto the z14 grid by `rasterize.py`
  (line geometry → covered cells; `docs/PLAN.md` §1 / §3). **Empty-tile
  signature:** an out-of-coverage tile is expected either as a `.pbf` with no
  `driveline` features or (for tiles fully outside the `bounds`
  `[-24.5326,63.2957,-13.4947,66.5665]`) as an HTTP 204 / 404 / empty body — the
  implementer must confirm the exact empty signature during the pilot and record
  it in §6. The presence test is feature-count-based, not status-code-based.

- **robots.txt / ToS notes; observed rate limit:**
  - **BLOCKER — IP block.** `*.ja.is` (the apex `ja.is`, the API
    `api-ja360.aws-prod.ja.is`, and the tile host `tiles.aws-prod.ja.is`) all
    return **HTTP 403 from an `awselb/2.0` load balancer to the project's
    scraping host on every path**, including `robots.txt`, the homepage, and the
    `.pbf` tile endpoint. This is an IP-reputation / geo-style block at the AWS
    ELB, **not** an endpoint or auth problem — the endpoint URL, scheme and
    layer structure are all correct (confirmed from the live map style JSON
    fetched via the un-blocked CloudFront asset host and the Wayback Machine).
    The implementer **must run the pilot and record the §3 fixtures from an IP
    that `ja.is` accepts** — an Iceland-based, residential, or commercial-VPN /
    proxy egress. See §6 "Open questions".
  - **robots.txt:** `https://ja.is/robots.txt` and
    `https://tiles.aws-prod.ja.is/robots.txt` could not be retrieved (same 403).
    The project's `polite.robots_allows` treats an unreachable / non-200
    robots.txt as **allowed**. Re-fetch `tiles.aws-prod.ja.is/robots.txt` from
    an accepted IP during implementation and record the real rule in §6; if it
    explicitly disallows the `tilesets/` path, **stop and escalate** rather than
    scrape.
  - **ToS:** Já.is content is © Sýn hf.; the basemap is also © OpenStreetMap /
    OpenMapTiles (per the style's `attribution`). This project stores only a
    **derived binary coverage raster** (presence/absence), not Já imagery and
    not Já's rendered map tiles. The `tilesets/v15/ja360` endpoint is
    undocumented (no public Já developer API). Treat as **polite-scrape
    default**: descriptive UA, low concurrency, throttle hard. Record the ToS
    caveat and the © Sýn hf. / © OSM attribution in the provider module
    docstring and the STAC item `tos_notes`.
  - **Observed rate limit:** unknown — could not probe. Be conservative:
    `polite.polite_fetch` with a per-host throttle (≈ 1–2 req/s, single
    connection), exponential backoff on 429/5xx, and **stop the run on a
    sustained 403 streak** (it indicates the IP block, not normal emptiness).
    Record the real limit in §6 once the pilot runs from an accepted IP.

- **Known quirks / gotchas:**
  - **IP block from non-Iceland infra** (above) — the single biggest
    implementation blocker; the live pilot and fixture recording cannot be done
    from the project's default host.
  - **Vector, not raster.** Unlike the kakao/naver/mapy redesigns, Já 360's
    coverage overlay is a **vector MVT** layer, not a rendered PNG. The
    `vector_mvt` kind decodes geometry; `rasterize.py` burns the lines onto the
    z14 grid. Do not look for an `alpha>0` PNG rule here.
  - **Coverage layer name is `driveline`.** The `ja360` MVT tileset's
    source-layer is `driveline` (the same word the bundle uses —
    `addLayer()`/`drivelineActivatedOn`). Set
    `SourceDefinition.layer_names=("driveline",)` so the decoder targets exactly
    that layer and the presence test is unambiguous.
  - **Tileset version `v15` is a static path segment**, not a token — pin it.
    If the style JSON ever advertises a new `vNN`, that is a re-scrape trigger.
  - **Tiles likely gzip-encoded.** MVT `.pbf` tiles are commonly served
    `Content-Encoding: gzip`; `vector_mvt.decode_vector_mvt` already calls
    `maybe_gzip_decompress` — no special handling needed.
  - **Iceland is large and mostly uninhabited.** The `ja360` source `bounds`
    cover the whole country, but coverage exists only along driven roads. The
    two-pass discovery runner should sweep at a coarse zoom first (the source
    supports z4–z14) so empty interior tiles are cheap, then fetch z14 only
    where pass-1 saw `driveline` features. See §4.
  - **Date attribute unverified.** Whether `driveline` features carry a capture
    year/date is unknown from our blocked host; the implementer should inspect
    decoded feature properties in the pilot and record the finding in §6. The
    date layer is out of scope for the initial PR regardless.
  - **Two layers, one source.** The style draws the same `driveline`
    source-layer twice (`casing` + main line) purely for cartography — there is
    a single `ja360` tile source and a single `driveline` data layer. Decode
    once; do not double-count.
